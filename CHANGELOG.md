# VictorBots changelog — Victorious Framework

## Unreleased (schema v5)

### Fixed (communications review, findings F1-F26 except F13 and F18)
- COMPANION_COMMS client: a call or receipt reply must name its request id (discovery, which carries none, may omit it); a mismatched or missing id is an unknown outcome, never applied. Versions outside 1..1 are a mismatch. JSON null reads as empty. One malformed capability no longer discards discovery. Null argument values are refused before sending; the reason is clipped without splitting a character. `CommsCodec.apply` checks the job's request id; `pending_approval` needs `ok:true`.
- One outstanding messaging request per app (`CommsClient` gate), buttons disabled while it runs, answer shown only if the screen is still alive; `MessengerComms` always unbinds and stops waiting when droidcommand-AI dies. A pending or running request is collected by tapping again (`CommsFollowUp`: same request id re-sent with a fresh nonce, or a receipt).
- Style profiles: imported and stored statistics are reduced to known numbers and vetted word lists before any guidance is built; imported expressions are short; examples capped at 50; confidence whitelisted; rollbacks keep the 100-version cap; 4-6 digit codes are never examples; words and phrases never keep digits and are not exported; analysis is capped at 2,000 messages. Deleting a profile clears communication bots that used it.
- Communication bots: hours must be both unset or both 0-23 and different; bad contacts or a missing mode are refused instead of crashing or being dropped; the activity log is capped on every path; `claimSend` checks and counts in one transaction.
- Backup now carries style profiles and communication-bot settings (no contacts, assignments or activity); unattended modes come back as Approval. MigrationTest covers the v3->v4 upgrade with data and cascades. No schema change. **Never run on a device.**

### Added
- Per-bot folders and "Share to…" (roadmap PR order step 8, item 7). More → **Bot folders**: choose one folder once with the system folder picker (Storage Access Framework, persisted grant, no storage permission). Each bot gets its own subfolder `<bot-name>-<short-uid>`; **Save to the bot folder** (message long-press menu and job artifact preview) and ⋮ → **Export this conversation to the bot folder** (Markdown of the visible turns) create new files only there. ⋮ → **Share this conversation…** and long-press → **Share to…** open the standard Android share sheet (text only). With no folder nothing is written; a grant removed in Android settings is detected and shown; names cannot escape the folder. The location is kept in app preferences, never in the database or backups (backup lists it as excluded). `BotFolders` (pure rules) + `BotFolderAccess` (SAF); 85 new JVM checks in `BotFoldersTest`. **No schema change. Never run on a device.**
- Per-chat provider switch (roadmap PR order step 2, item 8a). In a direct chat, tap **⇄** (or ⋮ → *Provider for this chat only*) to pick the DroidCommand AI path or any saved provider profile for that conversation only, or *Inherit*. The header says where the provider comes from: chosen for this chat, inherited from this bot, or inherited from the workspace default. The switch never edits the bot or the default, and `Gateway` still applies policy first, so it cannot loosen a policy. Memory suggestions, summaries, team chats and routines keep the bot's provider. `ChatProvider` + migration v5 (one nullable `chats.profile` column; deleting a profile clears it; not in backups). 43 new JVM checks plus v4→v5 migration checks; full suite green. **Never run on a device.**
- `StyleAnalyzer`, `StyleProfiles`, `CommsBots`, `CommsCodec` and migration v4 (additive). 150+ new JVM checks; full suite green.
- AGENTS.md rules for the communications area.
- `CommsClient` + `MessengerComms`: an outgoing COMPANION_COMMS client (certificate pinned before binding, reply accepted only from droidcommand-AI's uid, one send per call, never a retry) and More → DroidCommand → *Check messaging connection*. `not_sent` (job back to a draft) is kept apart from `no_reply` (outcome unknown, never re-sent). 43 new JVM checks. **No manifest change; never run on a device.**

- *List conversations shared with the assistant* on the same screen: the one-tap way to see a real read go VictorBots → droidcommand-AI → VictorSMS (read only, no model, nothing sent). 8 more JVM checks.

### Not done
